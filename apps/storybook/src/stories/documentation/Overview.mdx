# Documentation components

A documentation page is mostly prose, and prose is the part a design system usually leaves
to whoever is writing. This layer closes that gap: an author writes an `.mdx` file, and
every heading, paragraph, link, list and table lands on the Azion type scale, in the Azion
rhythm, without a single class in the source.

It has exactly two halves.

## 1. The prose layer

`DocProse` is the typography contract. MDX text compiles to plain semantic HTML — `h2`,
`p`, `ul`, `table`, `a`, `code` — and `DocProse` styles those descendants with the theme's
tokens. Nothing in the markdown carries a class, and nothing in the page overrides a token.

The rhythm comes from the docs.azion.com frame:

Because it styles descendants rather than itself, the same container works over any pipeline that
emits semantic HTML — the MDX renderer here, a CMS, or hand-written markup.

## 2. The component layer

Where prose runs out, an author reaches for a component. Each one is assembled from webkit,
so the surface, the severity colors, the keyboard model and the focus rings are the design
system's — this layer only decides the documentation-specific anatomy.

## The two halves meet in one file

`DocMarkdown` parses the MDX subset and renders both halves together: prose becomes plain
HTML inside `DocProse`, component tags become the components above. `DocPage` wraps that in
the page frame — masthead, previous/next, and an "On this page" rail built from the very
headings the body just rendered, so the rail can never list a section the page does not
have.

```vue
<script setup>
  import DocPage from '@aziontech/webkit-docs/doc-page'
  import source from './deploy-an-application.mdx?raw'
</script>

<template>
  <DocPage
    :source="source"
    :breadcrumb="[{ label: 'Start', href: '/start' }, { label: 'Deploy an application' }]"
    :next="{ title: 'Configure a domain', href: '/build/configure-a-domain' }"
  />
</template>
```

See **Example Page** for a real file rendered end to end, and **Authoring** for the syntax
an author may write.
