# Platform templates

The [components](?path=/docs/components-primitives-actions-button--documentation) are the primitives: a
button, a table, a drawer, a field. A template is one level up. It is a **page pattern**, a whole
block of a screen already composed from those primitives, with neutral copy (resources,
`resource-01`, `example.com`) standing in for yours.

Templates are named after the pattern they show, not after a product: a **Table view**, a
**Details page**, a **Multipage create**, a **Delete with confirmation**. Swap the nouns and
the data for your own resource and the pattern holds. Every "Show code" panel is a single SFC that
imports only `@aziontech/webkit` components, so it runs as pasted.

## How a screen is assembled

A screen is one shell, one header, then the blocks of its kind.

1. The **app layout** frames every signed-in screen: a full-height navigation rail and a content zone whose header carries the breadcrumb, the global Create and the account. Each page type (table view, details, settings, code editor, query editor, create) has its own frame inside it.
2. A **page header** names the screen and holds its primary action. Under a second-level tab bar each tab heads itself.
3. A **table view** stacks the property filter row, the applied filters and the table card. An **edit resource** page stacks settings sections and mounts the unsaved-changes bar once something is edited. Stacked fields anywhere are the `Field` components, never a hand-made label and control. A **create** flow leaves the app layout for the focused creation header.
4. **States** (first use, loading wires, drop zones) stand in for a block until there is data. Each task has its group below: **view**, **create**, **detail**, **edit**, **delete**, **settings**, **states**, **dashboard**, **auth** and **account**.

## Shell

Every page type sits in a frame: the chrome around it and the regions the page fills. The frames are the shells; the pages below are grouped by the task they serve.

- [Console shell](?path=/docs/templates-shells-console--documentation) — the signed-in frame: the resizable, collapsible navigation rail, the content header with breadcrumb and Create, and the list and detail layouts inside it.

## Page

The fragments every screen repeats are components, not templates. Compose them:

- [PageHeader](?path=/docs/components-primitives-layout-pageheader--documentation) — the page h1, its description and the page's own actions, at list, settings and hub sizes.
- [PageTabs](?path=/docs/components-primitives-navigation-pagetabs--documentation) — the full-bleed second-level navigation bar under a detail page's header, with the resource's actions on the right.
- [SectionHeader](?path=/docs/components-primitives-layout-sectionheader--documentation) — a band's title and description with its copy-link and actions, aligned to the card below it.
- [SettingsSection](?path=/docs/components-primitives-layout-settingssection--documentation) — the settings band: an anchored title with its hint over a card of rows, collapsible when it holds advanced settings.
- [SettingRow](?path=/docs/components-primitives-layout-settingrow--documentation) — the settings row inside a card: title and description left, control right or stacked when wide.
- [SaveBar](?path=/docs/components-primitives-layout-savebar--documentation) — the bar that commits a settings page or a create form: floating while dirty, docked, or the plain form footer.
- [ConfirmDialog](?path=/docs/components-primitives-overlay-confirmdialog--documentation) — the plain confirmation, the run-again confirmation, and the unsaved-changes guards (discard, or save or discard).

## View

- [TableView](?path=/docs/templates-platform-view-tableview--documentation) — the whole list page, header to table, with its filtered and empty states.
- [SplitView](?path=/docs/templates-platform-view-splitview--documentation) — an events explorer: controls and chips, the fields panel, the volume chart, the events table and the detail a row opens beside it.
- [QueryEditor](?path=/docs/templates-platform-view-queryeditor--documentation) — a data resource page: a resizable side panel beside the query editor and its results or templates, or beside the table browser and a table schema, and the empty database.
- [FileBrowser](?path=/docs/templates-platform-view-filebrowser--documentation) — a file store: folder breadcrumb, add files, and the files table.

## Create

- [CreationHeader](?path=/docs/templates-headers-creationheader--documentation) — the focused-flow header: back, product mark, breadcrumb, account.
- [SinglePageCreate](?path=/docs/templates-platform-create-singlepagecreate--documentation) — create in one screen: the creation header, the form column and the floating Cancel and Create bar, a long create's item groups over a full-bleed sticky footer, the required state after submit, and the Import from Git form whose sections of fields end in an inline Deploy.
- [MultipageCreate](?path=/docs/templates-platform-create-multipagecreate--documentation) — create one step at a time: the step rail, each step's settings, Back and Next.
- [CreateInDrawer](?path=/docs/templates-platform-create-createindrawer--documentation) — the create form in a drawer, the one every add or edit drawer inside a resource follows: a domain, an environment, a record, a deployment setting, a create drawer of item groups opened from a list, and the nested drawer that creates what a select needs and selects it back.
- [CreateHub](?path=/docs/templates-platform-create-createhub--documentation) — where a project starts: import from a repository or start from a template.
- [ProvisionWizard](?path=/docs/templates-platform-create-provisionwizard--documentation) — a two-step wizard: bind a project, then domain, environment, certificate and deployment.
- [SourceWizard](?path=/docs/templates-platform-create-sourcewizard--documentation) — create from a source: where it runs, then how it starts.
- [ResourcePicker](?path=/docs/templates-platform-create-resourcepicker--documentation) — choose an existing related resource or name a new one.
- [DeployDrawer](?path=/docs/templates-platform-create-deploydrawer--documentation) — deploy from a drawer: what to ship, its version and the resources it brings, then the build.
- [DeploymentFlow](?path=/docs/templates-platform-create-deploymentflow--documentation) — the deploy flow a create ends in: the provisioning steps with the build logs under them, through success or failure.
- [DeployTemplate](?path=/docs/templates-platform-create-deploytemplate--documentation) — deploy a template: connect Git, then the template's deploy form.
- [DeploySuccess](?path=/docs/templates-platform-create-deploysuccess--documentation) — the terminal screen after a deploy: the live deployment card, the resources created or bound, next steps.

## Detail

- [DetailsPage](?path=/docs/templates-platform-detail-detailspage--documentation) — a resource's detail page under its tab bar: overviews, versions, build, a deployment with its logs, and the summary card on its own for a resource, a service and a policy.
- [VersionDetail](?path=/docs/templates-platform-detail-versiondetail--documentation) — one version of a resource: its tabs, settings, the Save and Deploy bar, and the version history pane.
- [DeploymentLogs](?path=/docs/templates-platform-detail-deploymentlogs--documentation) — the deploy logs on their own: steps, log views and controls.
- [GetStarted](?path=/docs/templates-platform-detail-getstarted--documentation) — the CLI and CI steps to ship to a fresh resource.
- [AttachedResources](?path=/docs/templates-platform-detail-attachedresources--documentation) — the attached-resources table inside a resource with its Add action.
- [RecordTable](?path=/docs/templates-platform-detail-recordtable--documentation) — a zone: its main settings with nameservers and DNSSEC, and its records table.
- [ProductionChecklist](?path=/docs/templates-platform-detail-productionchecklist--documentation) — the readiness checklist card and its drawer.

## Edit

- [EditResource](?path=/docs/templates-platform-edit-editresource--documentation) — the settings tab of a resource: small header, sections of rows, and the unsaved-changes bar once something is edited, through its saving state.
- [AttributeEditor](?path=/docs/templates-platform-edit-attributeeditor--documentation) — key and value rows: the list page and its create drawer, with secrets, the JSON view and the scope band.
- [RuleBuilder](?path=/docs/templates-platform-edit-rulebuilder--documentation) — the richest form: a rule's criteria and behaviors, built row by row in a drawer.
- [CodeEditor](?path=/docs/templates-platform-edit-codeeditor--documentation) — a code resource page: the editor toolbar, one editor pane, or the editor and the arguments split by a resizable panel, and its Settings tab.

## Delete

- [DeleteWithConfirmation](?path=/docs/templates-platform-delete-deletewithconfirmation--documentation) — the destructive confirmation that asks for the resource name, as a copy chip over a bare input or as a labelled field in a dialog.

## Settings

- [SettingsForm](?path=/docs/templates-platform-settings-settingsform--documentation) — a settings form and its save strategy: item groups saved together by one sticky footer (the default), groups that each save from their own card footer, and cards that each carry their own Save.

## States

- [FirstUse](?path=/docs/templates-platform-states-firstuse--documentation) — a list's empty state before the first resource, with its ways to create and the promo cards.
- [PageWires](?path=/docs/templates-platform-states-pagewires--documentation) — the skeleton wires a screen shows while it loads.
- [ProjectIntake](?path=/docs/templates-platform-states-projectintake--documentation) — the drop zone over a screen and the initializing state of a project upload.
- [FormValidation](?path=/docs/templates-platform-states-formvalidation--documentation) — every state a submit can land in, one story per state.
- [FormError](?path=/docs/templates-platform-states-formerror--documentation) — a server rejection scoped to one section of a long form: the section `Alert` with its recovery action, reloaded in place until the form is valid again.
- [AsyncSubmit](?path=/docs/templates-platform-states-asyncsubmit--documentation) — a long-running submit after the form: idle, running, failed and succeeded, with its logs.

## Dashboard

Dashboard patterns built from the [chart components](?path=/docs/components-chart-overview--documentation), named after the job each one does.

- [HomeDashboard](?path=/docs/templates-platform-dashboard-homedashboard--documentation) — the home page in the shell, populated (greeting, usage band, resource panels) and empty (the onboarding prompt and starter doors).
- [AnalyticsDashboard](?path=/docs/templates-platform-dashboard-analyticsdashboard--documentation) — KPI tiles, charts and tables that all read the same period, with crosshairs synced across cards.
- [DataDashboard](?path=/docs/templates-platform-dashboard-datadashboard--documentation) — tiles with sparklines and period-over-period deltas, then the breakdowns behind them.
- [ServiceMonitoringDashboard](?path=/docs/templates-platform-dashboard-servicemonitoringdashboard--documentation) — status tiles, latency and error rate by window, and an alert rail.
- [SecurityDashboard](?path=/docs/templates-platform-dashboard-securitydashboard--documentation) — blocked and allowed over time, category and origin breakdowns, top sources and what needs attention.
- [ExecutiveSummaryDashboard](?path=/docs/templates-platform-dashboard-executivesummarydashboard--documentation) — a scorecard, goal bars against their targets, a trend grid of small multiples and a commentary column.
- [FunnelCohortDashboard](?path=/docs/templates-platform-dashboard-funnelcohortdashboard--documentation) — conversion tiles, the funnel with its drop-off between stages, and cohort retention.
- [CompositionDashboard](?path=/docs/templates-platform-dashboard-compositiondashboard--documentation) — how a total breaks into parts: total tiles, a stacked area over time, the current split and a ranked contributors table.
- [ProjectStatusDashboard](?path=/docs/templates-platform-dashboard-projectstatusdashboard--documentation) — completion, a dated milestone timeline, owners, the at-risk list and a burndown.
- [AlertsDashboard](?path=/docs/templates-platform-dashboard-alertsdashboard--documentation) — open alerts by severity: summary tiles, alerts per day stacked by severity level, the split by type, the entities with the highest risk and the open alerts with their SeverityTag.
- [HealthScoreDashboard](?path=/docs/templates-platform-dashboard-healthscoredashboard--documentation) — an overall score out of 100 with its band and trend, scores per application and location, hourly band strips and the open incidents.
- [ScanResultsDashboard](?path=/docs/templates-platform-dashboard-scanresultsdashboard--documentation) — items sent for analysis: summary tiles, the verdict split, where items came from, held and early-delivered items, and the filterable submissions table.
- [ActivityOutcomesDashboard](?path=/docs/templates-platform-dashboard-activityoutcomesdashboard--documentation) — outcome tiles, outcomes over time as stacked bars, breakdowns by actor, category and destination, and the request log with outcome and severity.
- [ConfigurableDashboard](?path=/docs/templates-platform-dashboard-configurabledashboard--documentation) — the reader arranges the cards: Edit layout turns on drag and resize on every card, with keyboard moves and Reset layout.

## Auth

- [Auth](?path=/docs/templates-platform-auth--documentation) — the signed-out screens under the auth bar: sign up, log in with its reset steps and the expired session, check your inbox, and every error a sign-in or sign-up can land in.

## Account

- [OnboardingForm](?path=/docs/templates-platform-account-onboardingform--documentation) — the three onboarding steps beside the app wireframe that follows them.
- [ChangePlanDrawer](?path=/docs/templates-platform-account-changeplandrawer--documentation) — the plan tiers in a drawer with the billing-period switch.
- [PaymentMethodCard](?path=/docs/templates-platform-account-paymentmethodcard--documentation) — the payment method on file, and its edit form.
- [Profile](?path=/docs/templates-platform-account-profile--documentation) — the profile page, and the layout every account settings page follows: sections of field rows and the unsaved-changes bar.
