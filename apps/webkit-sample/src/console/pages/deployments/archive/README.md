# Archive — Deployments implementations kept for reference, not mounted

Nothing in this folder is imported. Same convention as
[`../../resources/archive`](../../resources/archive/README.md): an implementation
replaced by a design direction, not a defect, kept whole so a rebuild starts from the
real file. Relative imports were re-pointed one level up so it still resolves if it is
mounted again; it is otherwise untouched.

| File                  | Was                                                                                                                                                                                                                                                                                                          | Replaced by                                                                                                                                                   | Why                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ReleaseComposer.vue` | The release composer at `/deployments/releases/new`: a page composing one release across workloads and resources, with Deployment Settings targets, per-resource versions, the dependency graph, an impact panel and a progress dialog. Every deploy entry routed here with its context in the query string. | [`ApplicationDeployDrawer`](../../../components/deployment/ApplicationDeployDrawer.vue) for applications; the workload page's own Deploy drawer for workloads | Deploying is now done from the resource being deployed (Figma `console.azion.com`, "Deploy Flow by Resource"): an application builds, then picks one version, one workload (bound or new) and one environment in a drawer. Composing many resources into one release was a separate surface nobody started from. `/deployments/releases/new` redirects to `/deployments`. |

Left in place because they are shared components, now used only by this file:
`DeploymentSettingsPicker`, `DeployProgressDialog`, `ImpactPanel`,
`ReleaseDependenciesSection`, `ReleaseTopologyTree` (in `components/deployment/`).
