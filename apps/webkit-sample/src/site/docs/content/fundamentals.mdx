A web platform is a service you build on instead of a stack you operate. You write the application and describe how it should behave, and the provider runs it on infrastructure it owns, filters the traffic that reaches it, and shows you what happened to every request. The servers, the routing, and the scaling stop being your work.

**Azion Platform** is that service on Azion's globally distributed infrastructure: the integrated technology and the interfaces where you build, secure, and scale applications, which includes operating and monitoring them. Use Azion Platform to run an application close to its users, block the traffic it should not receive, store the data it reads, and watch every request it serves.

## Platform resources topology

Everything that serves traffic on Azion is a set of Platform Resources bound to one another, with what you enable listed inside the resource it attaches to. The diagram shows how they connect: what the workload binds, what each resource holds, where the application fetches from, and what a function can call. Select a card to open it and read what it is and what it holds.

1. **Workload** (Required): Receives traffic. [Domains](https://www.azion.com/en/documentation/platform/workloads/domains.md), [Certificate Manager](https://www.azion.com/en/documentation/platform/workloads.md#certificate-manager). [Read the reference](https://www.azion.com/en/documentation/platform/workloads.md).

2. **Firewall** (Optional): Filters requests. [WAF](https://www.azion.com/en/documentation/platform/firewall.md#waf), [DDoS Protection](https://www.azion.com/en/documentation/platform/workloads.md#ddos-protection), [Bot Manager](https://www.azion.com/en/documentation/platform/firewall.md#bot-manager), [Network Shield](https://www.azion.com/en/documentation/platform/firewall.md#network-shield). [Read the reference](https://www.azion.com/en/documentation/platform/firewall.md).

   **Application** (Required): Serves content. [Functions](https://www.azion.com/en/documentation/platform/functions.md), [Rules Engine](https://www.azion.com/en/documentation/platform/applications/rules-engine.md), [Cache](https://www.azion.com/en/documentation/platform/applications.md#cache), [Image Processor](https://www.azion.com/en/documentation/platform/applications.md#image-processor). [Read the reference](https://www.azion.com/en/documentation/platform/applications.md).

   **Custom Pages** (Optional): Error pages. [Read the reference](https://www.azion.com/en/documentation/platform/workloads.md#custom-pages).

3. **Connector** (Required): HTTP or storage. [Storage connector](https://www.azion.com/en/documentation/platform/connectors/settings.md#storage), [Load Balancer](https://www.azion.com/en/documentation/platform/connectors.md#load-balancer), [Origin Shield](https://www.azion.com/en/documentation/platform/connectors.md#origin-shield). [Read the reference](https://www.azion.com/en/documentation/platform/connectors.md).

   **Store** (Optional): Data and files. [SQL Database](https://www.azion.com/en/documentation/platform/sql-database.md), [KV Store](https://www.azion.com/en/documentation/platform/kv-store.md), [Object Storage](https://www.azion.com/en/documentation/platform/object-storage.md).

   **AI** (Optional): Runs models. [AI Inference](https://www.azion.com/en/documentation/platform/ai-inference.md).

4. **Origin**: Your server. On-premises, Cloud, Colocation. [Read the reference](https://www.azion.com/en/documentation/platform/connectors.md).

1) A [workload](/site/docs/workloads) receives the traffic for its domains. It holds the [domains](https://www.azion.com/en/documentation/platform/workloads/domains/) and the certificate from [Certificate Manager](/site/docs/workloads#certificate-manager), and it binds, side by side, a firewall, an application, and a custom page set.
2) A [firewall](/site/docs/firewall) inspects each request before the application. You apply a [WAF](/site/docs/firewall#waf) rule set, [Bot Manager](/site/docs/firewall#bot-manager), [Network Shield](/site/docs/firewall#network-shield) lists, and functions to it. [DDoS Protection](/site/docs/workloads#ddos-protection) is always on, with or without a firewall.
3) An [application](/site/docs/applications) serves the content. Its [Rules Engine](https://www.azion.com/en/documentation/platform/applications/rules-engine/) applies behaviors, [Cache](/site/docs/applications#cache) answers repeat requests from a stored copy, [Image Processor](/site/docs/applications#image-processor) resizes images on the way, and [Functions](/site/docs/functions) run your code in the request path.
4) A [custom page set](/site/docs/workloads#custom-pages) replaces the default error responses with pages you control.
5) When the cache cannot answer, the application fetches the content through a [connector](/site/docs/connectors): an HTTP connector reaches your origin server, and a [storage connector](https://www.azion.com/en/documentation/platform/connectors/settings/#storage) reads an Object Storage bucket. [Load Balancer](/site/docs/connectors#load-balancer) and [Origin Shield](/site/docs/connectors#origin-shield) are enabled on the connector.
6) Functions call what the Store card holds, [SQL Database](/site/docs/sql-database), [KV Store](/site/docs/kv-store), and [Object Storage](/site/docs/object-storage), and what the AI card holds, [AI Inference](/site/docs/ai-inference).

To move an application that already runs elsewhere onto this chain, refer to [Migrate to Azion](https://www.azion.com/en/documentation/fundamentals/migrate-to-azion/).

## Interfaces

You create and manage every resource in the chain through the Platform's interfaces. [Azion Console](https://www.azion.com/en/documentation/guides/platform/account-and-billing/getting-to-know-azion-console/) is the web interface, [Azion CLI](https://www.azion.com/en/documentation/devtools/cli/) drives the same operations from a terminal, the [Azion API](https://api.azion.com/) exposes them over HTTPS for integrations, and the [Azion Terraform Provider](https://www.azion.com/en/documentation/devtools/terraform/) declares them as code. Azion's catalog groups what you enable on those resources into four categories: Build, Store, Secure, and Observe. For the request path and the table of what each resource holds, refer to [How Azion works](https://www.azion.com/en/documentation/fundamentals/how-it-works/).

## Your account

Everything you build on Azion lives inside an [account](https://www.azion.com/en/documentation/fundamentals/account-settings/). The account holds the resources, the people who work on them, the billing profile, and the security controls that apply to every sign-in. Each person signs in as a user of the account. The account owner creates teams and sets their permissions, and each user belongs to one or more teams that decide which resources they can view or change. A Group account also holds [client accounts](https://www.azion.com/en/documentation/fundamentals/accounts/), each with its own owner. Usage is metered per account and becomes an invoice on the [Billing](https://www.azion.com/en/documentation/fundamentals/billing-and-subscriptions/) page.

If you do not have an account yet, refer to [Create an account](https://www.azion.com/en/documentation/fundamentals/creating-account/). For the full model, refer to [Accounts, teams, and users](https://www.azion.com/en/documentation/fundamentals/accounts-teams-and-users/).
