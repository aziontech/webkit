One diagram instead of two

Proposal RV-Y1 · 2026-11-18 · open, owner to approve. TopologyDiagram and FlowDiagram become one component, here called NodeDiagram. It can be used “naked” and built by hand from parts, like FlowDiagram today, or given nodes and edges, in which case the default shows as much information as the data has.

Working prototype on branch proposal/unified-diagram: /components/node-diagram (live examples). Today’s pages: /components/flow-diagram, /components/topology-diagram.

Recommendation in plain words

  • Approve the merge. Both components already share the same drawing engine (TopologyDiagram reuses FlowDiagram’s connectors). The real difference is only what goes inside the boxes, and that is what the new parts and the data mode cover.
  • The default is the richest one. Give it nodes and edges and every box shows its icon, type, name (linked), place, status dot and text, figures such as latency or requests, and details that open. Lines can carry a label (18 ms, 502) and a colour.
  • Phones get a vertical rail automatically. The edge error page no longer needs a second hand-drawn list.
  • The bind menu becomes an add-on (NodeDiagramBind) you drop into the node’s action area, so simple diagrams don’t download a 15 KB menu.
  • Name: I recommend keeping NodeDiagram for the new one (the name Diagram is already the marketing drawing). Taking over FlowDiagram is possible but the part Parallel would still be renamed to Group, so it saves little.

Today vs proposed: topology

Same data. The new card shows status as a dot and text (like the error page and the rest of the console) and figures in a footer; the policy can still be changed, removed or bound with Apply and Cancel. The unbound Error page stays dashed.

Today vs proposed: request path (edge error page)

Equal boxes with uniform in both. The new one draws the failing hop as a red line labelled 502 and the timing on the good hop.

Today vs proposed: built by hand (“naked”)

Plain label boxes, a parallel group and one card built from parts. Connectors are the same engine.

The richest default

A service map from data only: edges set the columns, so the function and the cache that serve in parallel share one. Two lines entering the origin keep their own labels.

On a phone (390 px)

Today both scroll sideways inside a small box. The proposal stacks into a rail in reading order, labels beside it. Known limit: on the rail only the lines between neighbours are drawn; the full list of connections is still read out to screen readers.

What we gain and what we lose

Gained

  • One component to learn, document and test instead of two.
  • Rich cards for any diagram (metrics, location, details), not only the topology tab.
  • Real edges: lines between chosen nodes, with labels and colours, instead of “every node joins every node of the next column”.
  • Phones: a readable rail by default.
  • Screen readers hear every connection, not only the boxes.
  • Simple diagrams stop paying for the bind menu.

Lost or changed

  • Status changes from a tag to a dot and text (decision below).
  • The bind control is one extra import in the topology tab.
  • Topology column names (screen-reader only) are dropped in data mode; they remain on Group label when composing.
  • A composed-only page (hero, mock-ups) loads about 6 KB more than FlowDiagram’s root, for the data mode, loading and empty states.
  • On the phone rail, lines that skip a neighbour are not drawn.

What I looked at

  • Opened: Vue Flow node and edge guides (via its GitHub docs), React Flow custom nodes and accessibility, Grafana Node Graph, Datadog Service Map, Mermaid flowchart and architecture, Carbon flow charts, AWS Architecture Icons, Cloudscape component list, Cloudflare’s error page strip (via a generator that copies it). Partial: IBM technical diagrams (search snippets).
  • Grafana’s node (title, subtitle, main and secondary figure, icon, colour, detail fields) is almost exactly the rich card. Mermaid and Datadog lay out by depth from left to right, not by coordinates. Cloudflare’s strip is the request path, status as a dot and a word, stacked on phones. React Flow is the accessibility model (hidden description of the graph). Cloudscape and Carbon ship no diagram, and Carbon leaves layout to the app.

Decisions for you

  1. Merge the two into one? Recommended: yes.
  2. Name: NodeDiagram (recommended) or reuse FlowDiagram.
  3. Bind menu: separate add-on (recommended) or always built into the card.
  4. Status look: dot and text (recommended) or keep TopologyDiagram’s tag.
  5. Phones: stack by default (recommended) or keep sideways scrolling unless asked.
