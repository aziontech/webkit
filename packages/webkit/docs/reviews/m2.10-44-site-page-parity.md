# M2.10 row 44 — whole-page parity through `SitePage`

Date: 2026-11-13. Scope: every design-sample route that is rendered from page data by the sample's
`SitePage` (22 site pages and 29 `/site/lp/*` campaign pages, 51 routes), rendered again from the
same data by WebKit's `SitePage` and compared with the original.

## Method

- **Page data.** Each route's `*_PAGE` array (and each `lp/*` module) was loaded in Node from the
  sample's `site/data/pages` with `.vue` and asset imports stubbed. The sample sections' own prop
  defaults were read from their compiled `<script setup>`, so data the sample leaves to a default
  (`CompareSupportTiers`, `PricingPlans`, `TemplateGallery`, the hero client strip) is included.
- **Adapter.** A converter maps each sample entry `{ section, …props }` to the page JSON contract
  `{ _id, props, scenes?, gap? }`. It turns `actions[]` into `primaryAction` / `secondaryAction`,
  `Heroes` kinds into `hero-band` kinds, and scene components into scene-registry names. It also
  renames the nested shapes that differ, for example `quotes` to `items` and `files` to `codeTabs`.
  Unmapped sections and dropped keys are reported, not hidden.
- **Two renders.** The sample: its built app (`/site/<route>`), with the nav, the footer and the
  Design/JSON toggle hidden, and the theme switched to light for the light pass. WebKit: a consumer
  page that renders `<SitePage v-bind="page" />` on this branch's theme.
- **Capture.** Playwright 1.62 (container `mcr.microsoft.com/playwright:v1.62.0-noble`), widths 390,
  1024 and 1440, light and dark, reduced motion, animations and transitions frozen, after a scroll
  pass and `document.fonts.ready`. The `main` element is captured. Pixel diff: a per-channel delta
  above 25 counts, over the larger of the two boxes. 51 pages, 306 pairs.

## Results

Across the 306 pairs the mean is 17.1 % and the median 13.9 %. Because the diff is position
sensitive, once one band's height differs, every band below it counts as changed. A page is
usually structurally right with a high number.

| Page                                                                                                  | Mean      | Main cause                                                                                           |
| ----------------------------------------------------------------------------------------------------- | --------- | ---------------------------------------------------------------------------------------------------- |
| `resource-hub`                                                                                        | 91.4 %    | `article-index-resource-hub` renders all 139 rows; the sample shows 12 and a Load more button        |
| `website-bundle` (every section, one page)                                                            | 53.4 %    | Same paging gap on `article-index-blog` (104), `story-library` (35); `StepsList` unmapped            |
| `success-cases`                                                                                       | 49.8 %    | `story-library` renders all 35 stories; the sample pages them by 12                                  |
| `recognitions`                                                                                        | 36.2 %    | `media-split-stack` framed-image bands are about 25 % taller than the sample's                       |
| `careers-home`                                                                                        | 28.4 %    | `StepsList` (hiring process) has no WebKit section and is skipped                                    |
| `lp-*` with a `hero-form` (8 pages)                                                                   | 17–22 %   | `hero-form` has no paragraphs, link or form title; WebKit page is 248 px taller (form + closing gap) |
| Best: `lp-guia-alternativa-a-imperva`, `-f5`, `about`, `cloudflare-alternative`, `vercel-alternative` | 2.3–5.0 % | Type family only, as in M2.9                                                                         |

The type family (Rubik on this branch, Sora in the sample) lights up glyphs on every page, as in
`m2.9-site-parity.md`.

## What the renderer could not carry

- **Unmapped section:** `StepsList` (2 routes: `careers-home`, `website-bundle`). It renders
  nothing, and `SitePage` warns `no section is registered as "sample:StepsList"`.
- **Sample keys with no WebKit prop:**
  - `ClientQuotes` `eyebrow` / `title`
  - `StatsBand` `eyebrow` / `title` / `actions`
  - `HeroForm` `paragraphs` / `actions` / `formTitle` / `link`
  - `HeroWithOpening` `highlight` / `titleLength`
  - `MediaSplitStack` `description`
  - `MediaSplitBand` `mediaPadded` / `orientation` / `texture` / `linked`
  - `Heroes` `eyebrowPrefix` / `scenePlacement`
  - `ArticleHighlight` `fill` / `interval`
  - `FeatureTabs` code tabs
  - the paging props `pageSize` / `leading` of the index and library sections
  - `ArticleBody` `load` (the body loader) and `assistants`
- **Scenes:**
  - `FeatureWidgets` and `FeatureScroll` items carry `ProductWidget` fragments in the sample, but
    the WebKit items take only an illustration. Those cells draw no media.
  - `ConsolePanel`'s `DiagramSet` (one diagram per tab) is drawn as the first tab's `Diagram`,
    since the scene registry has no `DiagramSet`.
  - `RecognitionSealScene` maps to a framed image.
  - `ConsoleApplicationScene`, `ConsoleTraceScene` and `FunctionsHeroCanvas` are not used by any
    page-data route; they appear only on the hand-composed pages (`home`, `functions`). They plug
    into `src/assets/scene-registry.ts` when they land.

## Not covered

- The hand-composed pages, which are not page data: home, functions, cache, pricing, products,
  the solutions pages, the blog, careers jobs and others.
- The docs pages (`DocsLayout`, MDX).

Neither is rendered by the sample's `SitePage`.
