# M2.9 site-sections — visual parity with the design sample

Date: 2026-11-11. Scope: every piece WP site-sections took from the design sample (`origin/design/sample`,
`apps/webkit-sample`), rendered twice and compared pixel by pixel.

## Method

- **The sample was built.** A throwaway worktree of `origin/design/sample` (outside the repository's
  working trees, removed afterwards) installed with `pnpm install --filter webkit-sample...` and built with
  Vite. The sample's own `packages/icons/dist` was missing from the branch and was copied from this
  branch's build (the icon fonts are the same).
- **Same data on both sides.** The section props come from the sample's real page data, read from
  `site/data/pages/*.js` by a Node loader that stubs `.vue` imports: the Careers hero (`Heroes`
  `centered-band`) and hiring process (`ProcessScroll`), the AI Gateway capabilities (`CapabilityGrid`)
  and console panel (`ConsolePanel`), the Vercel alternative comparison (`CompareCompetitors`) and the
  Pricing plan matrix (`ComparePlans`/`PlanMatrix`). The cases with no page in the sample (StickyCarousel,
  QuoteBand, CustomerSpotlight, SectionCommand, the docs parts, LineFigure, the banners) share one fixture
  file. The console scene is the same placeholder box on both sides, so the frame, title, tabs and
  texture are what is compared.
- **Two harnesses, one per side.** The sample side renders the sample's SFCs with the sample's WebKit and
  theme; the WebKit side renders this branch's components with this branch's theme. Both wrap a section in
  `SectionContainer max-width="site"`, as the sample's `SitePage` does, and load the sample's `style.css`
  (font faces, icon fonts).
- **Capture.** Playwright 1.62 in the same container `vt-wk.sh` uses: widths 390, 1024 and 1440, light
  and dark, reduced motion, animations and transitions frozen, after `document.fonts.ready`. Each pair is
  compared with `pixelmatch` (threshold 0.1) over the larger of the two boxes. 19 cases, 114 pairs, no page
  errors on either side.

## What the differences are

1. **The type family (almost all of the text-bearing diff).** This branch's theme sets `--font-sans` to
   Rubik with Noto Sans Arabic (the RTL decision); the sample's theme sets Sora, which in the container
   also fell back to a system face. Layout, spacing, rules, registration marks, icons, colours and the
   texture are the same: the diff images light up glyphs only, which is also why the ratio grows as the
   width shrinks (the same text over fewer pixels). It is a theme difference that applies to every
   component, not a section difference, and is left as is.
2. **Line breaks from the type family.** A different face wraps a sentence a word earlier or later, which
   is the whole of the height differences of `CapabilityGrid` at 390 (two descriptions take one more
   line), `ProcessScroll` at 1024 and `ComparisonTable` at 1024.
3. **`ComparePlans` at 390.** `ComparePlans` existed before this package and was not rebuilt; the
   228 px are its rows: WebKit renders a row hint as `Hint` and a ticked cell as `pi-check`, the sample
   as a `Popover` `IconButton` and `pi-check-circle`, so narrow rows are a few pixels shorter each. Kept:
   `Hint` is WebKit's one shape for a term definition (M1 decision).
4. **`BannerArt` `globe`.** Same placement (the centre on the page's inline-end rule), same oversize and
   the same three-sided mask; the sphere itself is WebKit's `SpinningGlobe` (latitude and longitude grid,
   tilt) instead of the sample's `GlobeDisc` (flat disc with network rays). Decision recorded in
   `ui-craft-m2.md`: the system keeps one globe. The disc is sized off the band's own height through a
   size container (`100cqh`) instead of `100dvh - --banner-offset`; on a hero that fills a screen the two
   are the same length.
5. **`BannerArt` `network`.** The sample's `MapMesh` traffic (rays and packets) is not drawn
   (ROADMAP M2.10). The rest of the diff is the map's crop.
6. **Fixed during the check.** `ConsolePanel` and `CapabilityGrid` drew the first action filled where the
   sample's page data asks for an outlined one; actions now take `kind` (commit `c564e3eb8`).

## Not covered

Whole pages. The sample renders 60 site landings and the docs pages from page data through `SitePage`;
rebuilding them on WebKit needs a page renderer that maps every `section` name and its props (action
arrays, scene components) to WebKit sections. That is the marketing-site migration, M2.8, deferred
after the v6 release; it is an M2.10 row. Hub pages were not compared: the hub's foundations move to the
docs site (M2.5).
