# webkit ESLint plugin — `@aziontech/webkit/eslint-plugin`

ESLint rules that make **correct and performant** usage of the [`@aziontech/webkit`](https://github.com/aziontech/webkit) design system the default — enforced at lint time, in the editor, on commit, and in CI. The plugin ships **inside** `@aziontech/webkit` as a subpath export — there is no separate plugin package.

The catalog-backed rules read the **installed** webkit `catalog.json` (the version-locked manifest of allowed imports + token rules that ships inside the webkit package), so what the linter enforces always matches the webkit version the project actually has. If no webkit catalog can be resolved, the catalog-backed rules disable themselves and print a one-line warning — they never crash an unrelated repo, but they never fail _silently_ either. The construction-standard rules (`authoring-standards`, `prefer-define-model`, `no-style-override`) are catalog-independent and always run.

The import prefix the rules match is read from the resolved catalog, so it always matches the installed name.

## Install

```bash
npm i -D eslint vue-eslint-parser @typescript-eslint/parser
```

The plugin itself comes with `@aziontech/webkit`. `eslint` (>=9, flat config) is a peer dependency. `vue-eslint-parser` (+ `@typescript-eslint/parser` for `<script setup lang="ts">`) lints `<template>` blocks in `.vue` files — the config `npx @aziontech/webkit init` generates wires both.

## Usage (flat config)

```js
// eslint.config.js
import webkit from '@aziontech/webkit/eslint-plugin'

export default [
  // Pick one preset:
  ...webkit.configs.strict
]
```

## Presets

Nothing out of standard is ever a warning — **every rule in every preset is `error`**, except the heuristics (`HEURISTIC_RULES`: `container-needs-width`, which reads only the template and cannot see the rendered layout, and `no-output-in-command`, which reads intent from comments), so they `warn` in every preset.

| Preset        | Rule set                                                                                               |
| ------------- | ------------------------------------------------------------------------------------------------------ |
| `strict`      | every rule (default of `init`)                                                                         |
| `recommended` | every rule                                                                                             |
| `performance` | tree-shaking rules only (`no-barrel-import`, `prefer-tree-shakeable-root`, `no-whole-icon-set-import`) |

### File coverage

Every preset's `files` glob covers `**/*.vue`, `**/*.astro`, `**/*.js`, `**/*.jsx`, `**/*.ts`,
`**/*.tsx`, `**/*.mjs`, and `**/*.cjs` — `.astro` files are linted by the presets like any other
source file, no extra config required. Import/token/authoring-standard rules run on `.astro`
files exactly as they do elsewhere. The one exception is `no-style-override`: it needs
`vue-eslint-parser`'s template-body visitor to inspect class/style attributes on component tags
in a template, which `astro-eslint-parser` does not provide, so it is a **no-op** on `.astro`
files (it still runs its script-level checks, and it never throws). If your project hand-declared
its own `**/*.astro` override block re-listing rules to work around the previous gap, you can
remove it — the shipped presets now cover `.astro` on their own.

Consumers upgrading past this change will see new findings in `.astro` files that were
previously unmeasured by these presets — that's the fix working, not a regression.

## Rules

| Rule                         | What it catches                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `valid-import-path`          | An import of a subpath that is **not** a published export of the installed webkit version (with typo / singular↔plural suggestions).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `no-deep-internal-import`    | Reaching into internals — `@aziontech/webkit/src/**` or a path deeper than a published entry point.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `no-barrel-import`           | A barrel import / re-export / dynamic `import()` from the bare package, which defeats tree-shaking.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `no-whole-icon-set-import`   | Importing the entire `@aziontech/icons` set instead of per-icon subpaths.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `no-hardcoded-color`         | Hardcoded colors / raw palette / raw typography in class & style strings — use design tokens.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `no-hardcoded-motion`        | Motion outside the animation catalog: `duration-[…]`/`ease-[…]`/`animate-[…]`, literal ms / `cubic-bezier()` / `transition: all` in style strings, an `animate-*` name the catalog doesn't ship, or a static motion class with no `motion-reduce:` escape.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `no-physical-direction`      | Physical direction utilities in class strings (`ml-`/`mr-`, `pl-`/`pr-`, `left-`/`right-`, `text-left`/`text-right`, `border-l`/`border-r`, `rounded-l`/`rounded-tr`…, `float-left`, `scroll-ml-`…) that do not mirror under `dir="rtl"`. Autofixes to the logical utility (`ms-`, `pe-`, `start-`, `text-start`, `border-s`, `rounded-se`…). A horizontal or diagonal gradient (`bg-gradient-to-l`/`r`/`tl`/`tr`/`bl`/`br`, Tailwind v4 `bg-linear-to-*`) without an `rtl:`/`ltr:` gradient in the same class string is flagged too and autofixed by appending its mirror (`bg-gradient-to-r` → `bg-gradient-to-r rtl:bg-gradient-to-l`); the `{ gradients: false }` option turns that part off. The `left-1/2 -translate-x-1/2` centering pattern is allowed. Checks static `class`, `:class`, `class`/`className` in JSX/Astro, and `cn`/`clsx`/`cva`/`tv` arguments. |
| `prefer-tree-shakeable-root` | Importing a compound entry (`…/table`) when only the root `<Table>` is used — suggests the tree-shakeable `…/table-root`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `no-deprecated-component`    | Importing a component the installed catalog marks `@deprecated` — names the replacement.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `prefer-webkit-component`    | Reaching for a foreign UI library (or hand-rolling) where a webkit component exists.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `prefer-define-model`        | Hand-rolled `modelValue` prop + `update:modelValue` emit instead of `defineModel`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `no-style-override`          | Utility classes that fight a webkit component's internals instead of composing its slots / style seams. A static class of layout utilities (`w-full`, `max-w-*`, `self-*`, `shrink-0`, exported as `LAYOUT_CLASS_FAMILIES`) is allowed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `authoring-standards`        | The shipped construction standards (typed props/emits/slots, composable surface, deprecation shape) — same engine the DS hooks run.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `container-needs-width`      | (warn) A `Card`, `StatTile` or `ChartCard` placed as a direct child of a flex parent (`flex`/`inline-flex` in a row, or `flex-col` with `items-start`/`center`/`end`) without a width on it (`w-full`, `w-*`, `min-w-*`, `flex-1`, `flex-auto`, `grow`, `basis-*`, `self-stretch`, with or without a breakpoint). These are containers with no intrinsic width, so a content-sized flex item collapses to its content or to zero. Fix with `class="w-full"` on the component (an allowed layout class) or wrap it in an element with `flex-1`, `grow` or `basis-*`. A bound `:class` on the component, or a parent without a static class, is not checked.                                                                                                                                                                                                               |
| `header-search-trigger`      | Search in app headers goes through `SearchTrigger`. Flags a `GlobalHeader` that carries navigation (`GlobalHeader.Nav`, `NavigationMenu`, or a `Sidebar` in the same template) with no `SearchTrigger` in the template; any element but `SearchTrigger` with `aria-keyshortcuts` naming `Meta+K` / `Control+K` (a hand-rolled ⌘K field); and a `pi-search` `IconButton`/`Button` inside a `GlobalHeader` (the folded trigger, hand-made). Focused task headers (sign-in, create flows: brand, breadcrumb, avatar) have no navigation and are not checked.                                                                                                                                                                                                                                                                                                                |
| `no-wrapped-page-chrome`     | A `SiteFooter` or `SiteNav` whose parent element carries a border (`border`, `border-t`, `border-b`, …) or padding (`p-*`, `px-*`, `py-*`, …) in its static class, at any breakpoint. Both draw their own rules and frame: a bordered wrapper doubles the rule, a padded one pulls the frame off the page column. Render them as direct children of the page shell; a wrapper that only positions them (`sticky top-0 z-40`) is fine.                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `no-gap-after-closing-section` | A `SectionGap`, or a `FrameBox` holding a `TextureMaterial` (the hand-built closing frame), as the next element after `ClosingCallToAction`, `ClosingCallToActionNewsletter`, `ClosingCallToActionAgents` or `ClosingCallToActionTemplates`. Each of those draws the hatched closing frame itself, so a trailing one doubles the close. End the page column on the section, right above `SiteFooter`. |

| `no-output-in-command` | (warn) A shell code sample — an object with `language`/`lang` `bash`, `sh`, `shell`, `zsh` or `console` and a static `code` string, such as a `DocCodeGroup` sample or a `CodeBlock` tab, in a script or a template — that mixes the command with what it prints: a `#` comment after the command that reads as output (`# HTTP/2 200`, `# => …`, `# 4.23.0`, `# returns …`) or a trailing run of `#` lines, or, in a `$`-prompted transcript, a line without the prompt. A command block holds only what the reader runs, so its copy control copies exactly that. Fix with the sample's `output` field (`DocCodeGroup` draws it as a muted "Output" block), a `<CodeBlock kind="output">`, or prose. |

Deterministic import rules (`valid-import-path`, `no-deep-internal-import`, `no-barrel-import`, `no-whole-icon-set-import`, `prefer-tree-shakeable-root`) and `no-physical-direction` are **autofixable**.

The package holds its own code to the same check: `scripts/check-authoring.mjs` runs `no-physical-direction` over `src/components`, `blocks` and `examples`, and the repo ESLint config runs it on every `.vue` file (canaries: `lint-canaries/eslint/webkit/no-physical-direction.vue` and `no-physical-direction-gradient.vue`).

## How it fits the adoption toolkit

This is the **FORCE** layer: deterministic, blocks on commit and in CI. The companion **GUIDE** layer (the [webkit MCP server](./mcp.md)) helps an AI/dev generate correct code up front. Both read the same `catalog.json`. Wire everything in one step with `npx @aziontech/webkit init`.
