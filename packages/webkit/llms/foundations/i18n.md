# Languages (i18n)

> Built-in strings in en, pt-BR and es, the provider, useLocale and locale-aware formatting.

WebKit ships every built-in string in three catalogs: `en` (default), `pt-BR` and `es`. Wrap the app in `WebkitProvider` with a `locale` and every component follows it; `useLocale()` from `@aziontech/webkit/use-locale` gives your own code the same `t`, `dir` and `Intl` formatters.

## App-level setup (`setup` in the catalog)

A few components need **one-time wiring in the app entry before first use** — the catalog entry (and `get_component` on the MCP) carries it in a `setup` field. When `setup` is non-null, apply it BEFORE emitting code that uses the component, and check whether the project already has it (do not duplicate).

- **Toast**: fire-from-anywhere (`toast.success('Saved')`) only renders if a region is mounted. Wire the service once in the entry — `import { ToastPlugin } from '@aziontech/webkit/toast'` and chain `.use(ToastPlugin)` onto `createApp()`; the plugin mounts the region automatically (options: `app.use(ToastPlugin, { position: 'top-right' })`). A manually mounted Toaster also counts — never add both blindly (the store keeps only the first region active, but one wiring is enough). `npx webkit doctor` flags toast usage with no wired region.

- **WebkitProvider (languages)**: mount it once at the app root with the user's locale. Every built-in string a component ships (close buttons, pagination, empty states, assistive labels) then reads from the `en`, `pt-BR` or `es` catalog, and dates, numbers, file sizes and plurals format with `Intl` for that locale; `dir` follows the locale (`ar`, `he`, `fa`, `ur` are right-to-left). With no provider every component falls back to English. A label prop you pass still wins over the catalog; `messages` renames a built-in string for the whole app. Import it as `import WebkitProvider from '@aziontech/webkit/webkit-provider'`.

```vue
<!-- App.vue -->
<script setup>
  import WebkitProvider from '@aziontech/webkit/webkit-provider'
</script>

<template>
  <WebkitProvider :locale="user.locale">
    <RouterView />
  </WebkitProvider>
</template>
```

In your own components, `useLocale()` from `@aziontech/webkit/use-locale` returns the active `locale`, `dir`, `t(key, params)` and the `Intl` helpers (`formatNumber`, `formatDate`, `formatRelativeTime`, `formatList`, `formatFileSize`, `plural`), so your numbers and dates match WebKit's. `t` reads the provider's catalog; pass the English messages it should fall back to when no provider is mounted (`useLocale(en)`, with `en` from the same import).

Webkit components carry their own interface text: close buttons, pagination, empty states,
calendar fields, keycaps, wizard steps, screen-reader labels. Each one is read from a locale
catalog (`en`, `pt-BR`, `es`) through `useLocale`, so it follows the language set on
`WebkitProvider`. A string typed by hand next to the component, or passed into a prop to repeat the
default, is stuck in one language and drifts from the rest of the product.

## Do

- Leave a component's built-in text alone. `<Pagination>` already says "Previous page" and
  "Página anterior"; `<Dialog>` already names its close button; `<Kbd key-name="escape" />` prints
  `Esc` from the catalog.
- Set the language once, at the app root: `<WebkitProvider locale="pt-BR">`. Every component
  below it switches, dates and numbers included (`Intl` through the same locale).
- Rename a built-in string for the whole app with `messages` on `WebkitProvider`:
  `:messages="{ wizard: { submit: 'Deploy' }, kbd: { ctrl: 'Strg' } }"`. The keys are the
  catalog's (`group.key`); anything you leave out keeps the built-in text.
- Pass a prop only when the text is product copy specific to that screen (a dialog title, a field
  label, the action of this form), and write it by the `webkit-microcopy` skill: sentence case, one
  word per concept, no em dash.
- Format dates, numbers, file sizes, relative times and lists with `useLocale()`
  (`formatDate`, `formatNumber`, `formatFileSize`, `formatRelativeTime`, `formatList`), not with
  string concatenation.

## Don't

- Re-type a built-in string into a prop to "make sure": `close-label="Close"`,
  `placeholder="Select a Date Range"`, `next-label="Next"`. It freezes the English text and stops
  the provider's locale from reaching it.
- Fork a component, or wrap it, only to change one of its words: use `messages`.
- Hard-code key names (`Ctrl`, `Esc`, `Enter`) next to a `Kbd`: use its modifier props and
  `key-name`; `⌘`, `⌥` and `⇧` stay symbols on macOS.
- Build a sentence from fragments (`'Step ' + n + ' of ' + total`): plural rules and word order
  differ by language. Webkit's catalog keys take parameters (`Step {step} of {total}`).

## Example

```vue
<script setup lang="ts">
  import WebkitProvider from '@aziontech/webkit/webkit-provider'
  import Wizard from '@aziontech/webkit/wizard'
  import { ref } from 'vue'

  const step = ref(0)
  const messages = { wizard: { submit: 'Implantar' } }
</script>

<template>
  <WebkitProvider
    locale="pt-BR"
    :messages="messages"
  >
    <Wizard
      v-model:active-step="step"
      aria-label="Criar aplicação"
    >
      <Wizard.Step title="Configurar">…</Wizard.Step>
      <Wizard.Step title="Revisar">…</Wizard.Step>
    </Wizard>
  </WebkitProvider>
</template>
```

## Notes

- A `scope: general` standard: it applies to any screen in an app that uses webkit, not only to
  webkit's own components.
- Inside the package the same check runs at write time (the authoring hook) and in CI
  (`scripts/check-authoring.mjs`): a literal UI string in a component template attribute, or an
  English prop default, is blocked; the text goes to `src/i18n/messages/*.ts`.
- Product copy, the text no component ships, follows the `webkit-microcopy` skill.
